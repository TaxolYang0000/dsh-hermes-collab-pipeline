# Coding Agent 的下一步要怎么走

## ——为什么我们需要一个多agent讨论架构

> **原始版本：中文（Original: Chinese）**
> 英文版：[coding-agent-whats-next.md](coding-agent-whats-next.md)

---

## 一、起点：人的精力是瓶颈

AI的产出速度已经远超人的审核速度。一个Agent跑一个小时能写完一份完整的技术方案、生成几千行代码、产出十几份文档，人看完这些需要多久？远不止一个小时。单Agent模式下，你既是使用者又是审核者，每一份产出都要过你的眼睛。Agent干得越快，你的审核压力越严重。

这是最朴素的矛盾：AI把"干活"这件事自动化了，但"审核"没有。审核仍然是一个劳动密集型工作，而且审核的输入量随AI的速度线性增长。整条流水线上最慢、最贵、最容易累的那一环仍旧是人。

因此我们需要多Agent讨论架构的第一个理由不是认知层面的，而是精力层面的：一个人盯一个Agent已经累，盯多个更不可能。要想让人从过程监督里解放出来从而进一步提高工作效率，审核必须自动化，即Agent审Agent。

## 二、审核是单点：错的产出会一路流通

单Agent模式下，产出的质量完全取决于它自己。它觉得自己写对了，就交付了，没有人从第二个视角看过它。模型的自我评价不可靠：它对自己的产出有一种系统性的乐观，看不见自己埋下的错误前提。

现在采用人工审核当然能部分程度上解决这个问题，但仍然存在两个问题：

一是精力不够。AI产出的量摆在那里，人不可能逐行逐字审。

二是背景不够。AI用的工具链、代码库、上下文的量巨大，几乎不可能做到完全熟悉，很多不明显的错误几乎不太可能由人发现。

于是现实是：大量AI产出在"没人审过"的状态下被使用了。错的假设进入下一步，错误的代码上线，错误的方向浪费一整轮迭代。审核不是锦上添花，是质量的生命线，而这条生命线现在压在人身上。

这就是我们需要多Agent讨论架构第二个理由：审核必须从"人的义务"变成"系统的机制"。让另一个Agent来审，它有完整的工具链、能读代码库、能跑测试，它看得比人类快、比人类深、比人类全。人类只需要审它审出来的结论。

## 三、Agent互审要可靠：可能存在双板互研的虚假共识

综上所述让Agent审Agent是对的也是必须的，但两个Agent互审够不够？不够。机加工领域早就回答过这个问题。

精密机加工中，标准平面的制作采用刮研工艺。两块平板互研，永远得不到高精度平面：如果一块凸、一块凹，它们互研会完美贴合，但两块都不是平面，误差被互相适应了。三块平板闭环互研（A对B、B对C、C对A）才行：任何一块的凸起都会被另外两块暴露，循环下来三块才有可能都逼近真平面。

双agent互审就是双板互研。A审B、B审A，两个Agent可以互相认可彼此的盲区，达成一个"一致但都错"的结论，它们不是找到了正确答案，是互相适应了错误。尤其是同源模型：同一个供应商的模型共享同一套训练数据、同一种思维偏差，A看不见的B也看不见，A审B，B审A等于完全没审核。

要破除虚假共识，需要闭环：至少三方循环互审（A审B、B审C、C审A），任何单点的错误都会被与它不互补的第三方抓住。异构（不只是不同的harness架构，更是不同的模型）进一步降低同源盲区的概率。这就是为什么"审核自动化"不是简单的"两个Agent互相看"，而必须是一个结构，闭环的结构。

## 四、多Agent讨论架构：审核应该有固定机制

把审核变成机制，我目前的看法是必须有四个要素，四个要素缺一不可：

一是独立生成（round start）。问题下发给各方，各自先出方案，互相不可见。先看到别人的方案会锚定自己，第一个方案会变成所有人的参照系。独立生成保证各方带着真实的独立立场进入讨论，而不是带着对第一个方案的附和。

二是闭环互审（cross-review）。所有方案全量分发，每方必须对另外每一份方案提出支持的部分，具体问题和改进点。这是把刮研的三板闭环落到协议里：A审B、B审C、C审A。强制提出"Pros and Cons"是把形式上的附和变成真正的对照。

三是有界收敛（synthesize）。带着新意见进入下一轮，直到收敛。收敛显式定义，目前我认为三条满足任一即可停止：意见一致、完成固定轮数或者连续三轮无变化。不设限制的讨论会变成无限烧钱；没有分歧固化的检测讨论会变成各说各话的循环。

四是人类终审（final judgement）。讨论的产出是"统一建议加残留分歧清单"，最后由人类真正决定。

相比与现在普遍的单Agent形式，在这一整套架构下人类的角色变了：从"每一份产出都审"变成"只审最终结论"。

## 五、这套架构的意义是什么：人的精力应该花在终审

人最宝贵的是判断力。终审和过程审核消耗的判断力完全不同：

过程审核，面对的是大量细节，代码对不对、文档全不全、有没有遗漏。这是体力活，消耗注意力，而且AI比人类快，人类永远在追赶。

终审，面对的是少而关键的信息，三方的方案、交锋记录、分歧点。这是负责判断，消耗的是洞察力，AI已经把完整的工作真正做完了，人类只需要做决定。

多Agent讨论结构的价值，就是把人类的精力从"审细节"挪到"做决定"。细节交给Agent互相审，人类只看：方案之间冲突在哪、分歧为什么没消除、哪个方案更符合目标。人类审的东西变少了，但每个都更有价值，更直抵核心。

这不是把决策权从人类手中拿走，而是把决策所需的信息完全整理好。

## 六、讨论需要分级：AI预算的问题

讨论并不是一个低成本的事情，每轮都是多个模型调用，成本随轮次放大。所以讨论必须分级，按任务价值启用：

低风险、目标清晰的任务：直接执行。一个Agent干完，另一个不审核或者简单审核就够了。

中风险任务采用双模型互审：一个实现一个审查，强制异构配对。

高风险、模糊、战略性问题采用全量讨论。三方独立生成，闭环互审，有界收敛，人类终审。

分级的意义：把预算花在真正需要的地方。给"写README"开三方讨论是浪费，给"架构选型"开三方讨论是应该。判断标准只有一个——这个决定错了的代价有多大。代价大就讨论；代价小就直接执行。

分级也是精力预算的一部分：人类的精力有限，讨论结构要保证每一次人类深度参与的审核和讨论都花在值得的决定上。

## 七、落地形态

目前我手中的测试下讨论结构最终落在kanban上，因为kanban已经是验证过的硬记录面：

每一轮等于一组kanban任务（round start建任务，各方认领产出，回写position）。

交叉审查等于依赖关系（task_links天然表达"审查任务依赖实现任务"）。

收敛判定等于watcher侧状态机（满足三条件任一，自动进入synthesize）。

产出存档等于统一建议加残留分歧清单，作为任务前置决策，可复用、可审计。

每一步都有记录，每一次交锋都留痕。讨论不是聊天室，是带状态机、带审计、带预算的工程结构，你随时可以回去看任何一个决定是怎么讨论出来的。

## 结语

回到起点：人的精力是瓶颈，审核是单点。多Agent讨论架构要做的，是把审核从人身上卸下来，变成系统的机制；把人的精力从过程监督里解放出来，只留给终审。Agent的三板互研不是仪式而是是数学，两块板可以互相适应成完美贴合的曲面，只有第三块板能把假象拆穿。Agent独立生成保证立场真实，闭环互审保证错误无处藏，有界收敛保证讨论会结束，人类终审保证决策权在人类。多Agent讨论架构并不是把简单的事变复杂，而是把"人的精力有限"这个在以后可能限制Coding Agent使用的问题真正解决的可能方案。

## 附：对本文的批判与成立条件

觉得很完美？但是该泼点冷水了。

本文的论证并非没有前提。我们默认了审核量是外生的、不可消除的——而它其实是工作流质量的函数：提示词清晰、任务拆解到位、SOP 注入充分，产出质量在源头就被控制，末端审核可以退化为抽样验证（线性工作抽查 5% 即可验证 95%，非线性 20% 验证 80%，帕累托原则）。我们默认了审核必须由另一个 Agent 来做、且 AI 审核全面优于人——而人审抽样与人机分工的成本结构完全不同。我们借用了刮研的类比，但刮研有客观真值（平面度），AI 互审没有——收敛到的可能只是多数共识，不是真相。我们默认了"强制提出 Pros and Cons"能区分形式附和与真正对照，但谁来判断质疑的真伪？AI 不具备真值，权威不在场。我们默认了人类终审可靠，但人的决策力同样有限，终审一个黑箱结论与信任一个黑箱区别不大。我们默认了讨论的收益大于 token 成本，却没有建立可度量的 ROI——把 token 消耗换算成人类完成同等验证所需的大脑工时、再换算成市场劳动回报，这个账没有算。而这一切的根是一个更深的假设：使用者无法控制 AI 的产出过程，所以只能在末端兜底。如果换成另一个立场——使用者能控制过程（拆解、SOP、抽样验证）——本文从一开始就不应该存在。多 Agent 讨论架构可能确实存在价值，但是在本文中更多的是被神化了：它的真实价值是训练集的并集，覆盖更多盲区，但增益有限且边际递减。质量来自设计，不是来自审核。人机平权，谁擅长什么谁干——这才是本文真正该抵达的结论。

那么，这篇文章什么时候才是真的？批判指出的这些假设它们是一棵从根上分叉的树，起点只有一个：使用者无法控制 AI 的产出过程。"无法控制"有四种含义，任何一种是真，文章的前提就成立：物理上的无法（AI 产出的复杂度超过人脑理解上限）、能力上的无法（使用者不是该领域专家或者说在该领域无法超越AI）、规模上的无法（任务量超过单个人能维护的边界）、信息上的无法（过程不可观测，黑盒模型、分布式执行）。反过来，一个人如果能拆解任务、能注入 SOP、能抽样验证，他就不在这个前提的覆盖范围内。所以文章的真实读者不是"使用 AI 的人"，是"被 AI 使用的人"。

再远一点，审核交给 AI 之后，整个架构的技术命门出现了：AI 互审有没有真值？刮研类比在这里第一次暴露它的边界。刮研有客观真值——平面度是物理量，三块板收敛是在逼近真实。AI 互审没有这个锚点：A 说 B 的方案有漏洞，B 反驳，谁对？没有外部标准，收敛到的可能只是多数共识，不是真相。只有当验证可以自动化的时候——代码有测试、数学有证明器、物理有模拟器——互审才从空转变成有据可依：A 质疑 B，B 可以跑测试反驳，质疑会被事实检验，强制"提 Pros and Cons"才真正触发对照。这是整篇文章最脆弱、也最值得期待的一环：它不取决于论证，取决于工具链的成熟。

再往上是人的位置。当过程交给 AI、验证交给工具，人退到终审。终审可靠吗？取决于终审的对象。如果终审的是技术细节黑箱，人没有判断力；如果终审的是价值、目标、偏好——哪些目标值得追求、哪个取舍符合伦理——那是人的主场，AI 没有训练集覆盖那里。所以人的终审权不是天然的，它有个隐藏条件：终审必须落在人真正擅长的领域。否则，终审一个黑箱结论，和信任一个黑箱，没有区别。

最后是经济账，也是唯一随时间变化最快的一条。整个体系要划算，token 成本必须低于人审成本，错误代价必须高于讨论成本。这个条件今天不成立——纯语言互审烧 token 且无锚点；而在遥远的未来或许成立——模型变强、任务变复杂、人相对变弱，而 token 越来越便宜。三线汇合的那一天，这篇文章就从愿景变成现实：根条件成立（确有大量无法控制过程的人），技术线打通（互相审核的验证可自动化），经济线反转（AI 互审比人审便宜）。

人类社会的同行评审已经运行了几百年，它之所以有效，是因为实验可复现这个锚点在审稿体系之外兜底。AI 互审要做的，是把同一个锚点搬进机器世界——当代码有测试、方案有模拟、判断有验证，多 Agent 讨论就不再是"用更大的垃圾掩盖垃圾"，而是真正的同行评审。
