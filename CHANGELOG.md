## v0.2.0 — 2026-08-14 · Session Inheritance (M6)

### New
- **Watcher session inheritance** (dsh-kanban-watcher v0.2.0):
  - When a task body carries `[会话继承:<keyword>]` or `[会话继承:<session-id>]`,
    the watcher matches a historical session in the same workspace and **continues
    its context** (no longer a fresh conversation every time).
  - Three execution modes (validated by the S1 spike):
    - `live-reuse`: target session is still running → reuse directly (scheme A)
    - `resume`: target is a cold session → `agents.resume` restores the event stream, then continue
    - `create`: no match → fall back to a new session (original behavior)
  - Result write-back includes an audit field: `继承会话: <sessionId>`
  - Token guard: estimates tokens before resume, warns to create a new session above 500k
  - Session-level guard: if the same session is hit by a second task, skip inheritance to prevent double-running
  - cwd special-case: resumed sessions keep their original cwd (header is immutable); conflicts with `--workspace` are only logged
- **/dsh-send skill v1.3.0** (Hermes side):
  - New `--resume <keyword>` option: writes `[会话继承:<keyword>]` into the task body
  - Example: `/dsh-send --resume keep-discussing-X analyze the conclusion from before`

### Changed
- Watcher source: 337 → 588 lines (parseInherit / matchSession / driveAgent /
  resumeOrReuse / estimateResumeTokens / session-level guard)
- 46 unit tests + 10 integration tests, all passing (0 failures)

### Fixed
- Previous behavior: every dispatch started a new conversation. Now historical

## v0.1.0 — 2026-08-14 · Initial Release

### New
- **dsh-kanban-watcher plugin v0.1.0**: watches the Hermes kanban board `dsh`,
  hands ready tasks to a DSH Agent in a Web GUI session, writes results back to
  the board + a done file
  - Event-driven wake-up (trigger file + fs.watch + 30s fallback polling)
  - Atomic claim (no duplicate execution), serial execution, crash recovery
    (singleton lock + reclaim)
  - Model translation (modelMap), output whitelist, hermes-trusted permission preset
- **external_event_steer** (Hermes cli.py + config_defaults.py patch):
  - The CLI session watches `~/.dsh/kanban-done/` while idle; a new done file
    injects an "External Notification" into the running session
  - Done files are treated as untrusted input (only id/title/result read,
    truncated, control chars stripped, never executed)
  - Config toggle `features.external_event_steer` (default off)
- **/dsh-send skill v1.2.x**: Hermes-side dispatch (model / workspace / idempotency key / skill transfer)
- **install.sh**: one-command automated setup (idempotent, agent-friendly: `--yes` full-auto, `--dry-run` preview)
- **Docs**: bilingual README, INSTALL guide, NOTICE (attribution), capability survey & feasibility
