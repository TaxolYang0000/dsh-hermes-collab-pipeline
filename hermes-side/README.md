This is the **Hermes-side** change in the DSH↔Hermes dual-agent collaboration pipeline.
It lets a Hermes CLI session notice when an external agent (e.g. the DSH watcher)
finishes a task — no board polling, no manual input. When a task completes, an
"External Notification" pops up automatically in the session.

## When to use

You run **Hermes Agent** (CLI or interactive session) and:

- Have an **external executor** (e.g. the DSH / DeepSeek Harness watcher plugin)
- It can write a JSON file to a fixed directory after completing a task (default `~/.dsh/kanban-done/`)
- You want the Hermes session to **notice completions proactively** instead of checking manually

Typical flow: Hermes dispatches → DSH executes → writes a done file → Hermes session
auto-pops 「任务 xxx 已完成。结果摘要：...」.

## How it works

```
DSH watcher completes a task
      │  writeDoneFile() → writes ~/.dsh/kanban-done/<id>.done
      ▼
JSON file ({id, title, result, ts, status})
      │  Hermes CLI idle loop polls _drain_done_notifications() every 0.1s
      ▼
New .done file detected (not in the seen baseline)
      │  id/title/result extracted, truncated, control chars stripped
      ▼
Injected into _pending_input → session auto-pops "External Notification"
```

## Security design

- Done-file JSON is treated as **untrusted input**: only `id`/`title`/`result` are read
- Values are truncated (id 40 / title 60 / result 200 chars) and control characters stripped
- File content is **never executed** — only assembled into a text message
- A seen baseline is built at startup: existing files are not replayed, only new events
- The feature is **off by default** (`features.external_event_steer: false`), opt-in

## Known limitations

- Only affects **CLI sessions** (cli.py main-loop idle branch); gateway/Feishu etc. do not use this injection
- Seen-baseline timing: done files already present when the directory first appears are
  treated as baseline and skipped (when testing, ensure the dir exists and is initialized first)
